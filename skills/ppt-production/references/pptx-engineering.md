# 排版与文件工艺

以下规则在相应操作发生时必须执行。具体 API 与尺寸预算有版本和字体条件，换环境要验证，不可照抄后宣称安全。

## 1. 排字与渲染测量

- Arial 20pt 英文可按粗体约 `0.14in/字符`、常规约 `0.115in/字符` 初步预算。粗体每行字符数约为 `(框宽 - 0.25in) / 0.14`，行高约 `0.36in`，框高至少 `行数 × 0.36in + 0.1in`。另留约 10% 余量，最终以实际渲染为准，不能把英文预算直接用于中文。
- Arial 20pt 下，约 10 字符及以上的粗体长词，不得硬塞进小于 1.6in 的窄框。表格列宽按最长表头的实际宽度加至少 0.1in 余量确定，不允许拆断单词。
- 换行项目符号使用悬挂缩进，可用 `marL="256032" indent="-256032"` 作为起点，再按字号与模板调整。用 PowerPoint 列表属性设置，不把圆点写进关键词之间。
- 页面中轴为 `页面宽度 / 2`。底部结论条按文本行高与内边距设置，右缘必须位于页码区左侧，并至少留 0.1in 间隙。页码区域以当前模板的实际位置为准。
- 中文和中英混排必须按实际字体、字号与渲染结果测量，不能套用其他字体的固定字宽。出现压线时用 PyMuPDF `rawdict` 的字符边界框核对，不能用含空格的 span 宽度得出假结论。
- 从像素换算坐标前先读取图片实际尺寸，不能猜 DPI。PDF 坐标换算英寸用 `pt / 72`。位图内部文字无法依靠 PDF 文本提取验收，必须查看渲染图，必要时测量图中文字。

## 2. 换图、裁图与 PDF 修补

- 按 shape name 或其他稳定身份定位目标图片，先记录原几何、裁切与关系。替换后检查纵横比，调整图框并重新居中，禁止把圆拉成椭圆。
- 检查 `blipFill` 下的 `srcRect`。不适用旧裁切时仅清除或重设目标图的裁切，禁止全稿清除，否则会误伤 logo 和用户有意裁切。
- 图片部件可能被多个 shape 或页面共享。替换 `_blob` 前检查引用，若会误改其他页，为目标图片建立独立部件。
- 与最终版原始资料中的图片逐张核对面板数、图例、标签与结论。相同尺寸原图可用像素差辅助核对，裁切图并排检查，不凭单一模板匹配分数判定版本。
- 裁剪图表面板用文字锚点或实际图形边界定位，禁止目测比例坐标，不能把邻栏文字残片裁进图内，也不能删掉重要的溢出标签。
- 修补源 PDF 一律在副本上进行。可提取文字用 `get_text("words")` 定位，再用 redaction 与 `insert_text` 修补。Type3 或无 Unicode 字形用 `get_drawings()` 定位路径，局部覆盖后补字，匹配原字体大小与颜色。源版本改变必须重新定位，不能复用旧坐标。
- 密集图阶段高亮优先用模板强调色的无描边半透明色块。注意 `a:alpha val="22000"` 表示 22% 不透明度、78% 透明度，不能混淆。描边框仅在留白充分且不压线时使用。

## 3. 复制、合并与 XML 红线

- **禁止同时全量重编号 `p:cNvPr` ID 与改写 `a16:creationId` GUID。** 该组合有触发 PowerPoint 修复及页面内容丢失的风险。
- 跨稿复制形状必须处理 `p:tags` 关系、页内形状 ID 和遗留 `mc:AlternateContent`。`shapes` 遍历或 `clear_content()` 可能漏掉包裹在 AlternateContent 中的形状，必须补扫，并检查母版、版式上的隐藏遗留内容。
- 跨 PPTX 复制页必须使用**目标包**的 layout，按名称匹配合适版式，禁止把源包的 `slideLayout` 直接传给目标 `add_slide()`。
- 复制关系时跳过源 slideLayout 与 notesSlide，重新建立有效关系并记录旧 rId 到新 rId 的映射，重写形状树全部 `r:` 命名空间属性。源备注单独复制到目标备注页，不能直接挂源备注关系。
- python-pptx 1.0.2 的 `_add_relationship(reltype, target, is_external=...)` 返回新 rId，不接受指定 rId 参数。禁止把旧 rId 作为 `is_external` 传入。操作私有 API 前核对当前版本签名。
- 复制形状树时只追加 `sp`、`pic`、`graphicFrame`、`cxnSp`、`grpSp` 等有效形状，删除自动占位符，并单独处理其他必需内容。
- 图片通过目标包的 `get_or_add_image_part(io.BytesIO(blob))` 按内容去重或新建，不能直接挂源包同名 `imageN.png` 部件。图表、嵌入对象等也要完整复制依赖并重映射关系。
- 删除中间页后再加页，检查 `slideN.xml` 名称是否碰撞。插页需调整 `sldIdLst`，目标位置只加排在前面的新增页数，防止重复计入自身。保留模板母版的 `slidenum` 字段自动编号，重排后核对页码、备注和渐进顺序。
- 检查每个 `prstGeom/avLst` 内 `gd` 的 `name` 唯一，重复参数名会引起 PowerPoint 修复。修改参数应更新现有项，不追加同名项。若重复值不同，必须确认正确值，不能盲目保留首项。
- 继承样式优先复制同稿样式形状后局部修改。多段文字应保留段落与 run 格式，不用 `tf.text = ...` 覆盖全部富文本格式。

## 4. 写盘与不误改验证

- 所有修改完成后保存一次到临时文件。检查 ZIP `testzip()`、重新加载、ZIP 成员名无重复，再替换目标文件。出现 `Duplicate name` 警告按失败处理。
- 若原件被失败保存写坏，立即恢复备份。源文件在处理期间发生变化时，基于新版本重新合并本次改动，不覆盖用户更新。
- 用户要求其他页完全不动时，检查非目标页的内容、几何、备注、图片和共享部件。python-pptx 保存可能重序列化全包，也可能回收无引用图片并复用名称，不能只比较 `slideN.xml` 就声称没有误改。
- 若明确要求字节不变，只替换目标页所需的部件及依赖，其余 ZIP 成员保留原字节，使用全新文件句柄逐成员校验哈希。若仅要求内容与样式不变，可以规范化 XML 比较语义并检查渲染，不能把语义一致当作字节一致。
- 写 ZIP 时用 `writestr(字符串名, 数据)`，不复用源 `ZipInfo` 对象。其 `header_offset` 会被写操作改动，复用旧读取句柄会产生错误或假通过。审计失败不得落盘，落盘后再次重载确认。

## 5. 渲染与真实 PowerPoint 验收

- 可先用 LibreOffice 转 PDF，再用 `pdftoppm` 或 PyMuPDF 渲染图片。并行任务必须有各自的 `-env:UserInstallation=file:///...` profile 和输出目录，临时文件名前缀包含任务或页号。
- 先试渲染一页确认中英文字形完整。若 LibreOffice 使用 `--headless` 时出现 CJK 缺字，尝试去掉该参数并对比。独立 profile 缺字体时检查字体可用性，必要时放入其 `user/fonts`，不能把环境缺字当作内容正常。
- LibreOffice 和 PowerPoint 的回退字体及字宽可能不同，一个渲染器显示正常不保证另一个正常。必须实际查看目标软件结果。
- PowerPoint 打开可能自动保存，所以测试一律用副本，并核对原件 mtime。macOS 显式使用 `open -a "Microsoft PowerPoint" ...`，确认实际打开的是测试稿，防止被 LibreOffice 接管。
- 自动检测器先用已知良好文件验证。AppleScript 的 `User canceled` 或 `NO PRESENTATION OPEN` 只能作为排查信号，必须区分真实修复弹窗、打开了错误应用、恢复窗口或脚本失败。已知良好文件也失败时先修复检测环境。
- 排查应用状态时只清理本任务创建的进程、锁文件和临时 profile。不得无差别杀掉用户应用、删除恢复状态或丢弃用户未保存内容。
- PowerPoint 打开无修复提示、页数正确、无空白页与缺失内容才算通过。即使 LibreOffice 能渲染，也不能据此证明 PPTX 无兼容问题。

## 6. 仅在用户明确要求动画时

默认禁止 transition。只有当前用户明确要求时才应用本节，不能因采用渐进副本就自动加入动画。

- 用户要求 morph 时可使用 `p14:morph option="byObject"`，时长按讲述节奏确定。先清理目标页既有 transition，按 schema 位置插入并验证，不能叠加多份 transition。
- 跨页匹配形状同名，需强制匹配时用 `!!` 前缀。静态元素同名同位，避免意外漂移。兼容 fallback 必须也符合用户允许的动画范围。
- 渐进页必须逐阶段增加信息，删除节点同时删除相关连线，完整版置于组尾，备注随阶段更新。阶段标签必须符合主文件的文案与标点规则。
