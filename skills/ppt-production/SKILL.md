# PPT 制作与修订

以下是必须执行的规则。除用户对当前任务明确另有要求，不得自行放宽，不得把硬性检查改成建议。精简说明不等于删减验收标准。局部修订只改指定范围，既有问题应报告，不借机重做其他页面。

## 一、制作流程

1. **制作大纲**：先读最新版资料与参考稿，逐页列出标题、核心结论、证据和拟用图片。页数服从讲述节奏，内容拥挤时拆页补充解释，不增加单页文字密度，不擅自添加备份页。
2. **询问用户，明确问题**：带着大纲澄清受众、用途、时长、重点、视觉基准和交付要求。已知信息不重复问，关键分歧明确后制作，用户已授权自行决定的部分直接推进。
3. **搜集素材**：按页搜集并查看原图、图标、论文图表与数据，记录来源、版本和使用页。先备好素材，再确定布局，禁止做完纯文字页后把配图留给用户。
4. **并行 agent 制作**：按页或章节分工，向每个 agent 下发大纲、素材、本 skill 的全部硬规则和任务适用的附录。使用独立输出文件、临时目录与渲染环境，主 agent 统一合并。局部单页修改可直接制作，不能省略后续验收。
5. **审核校验**：执行第四节的程序检查、逐页视觉检查和至少三轮子 agent 交叉验收，禁止仅凭生成成功或缩略图宣布通过。
6. **迭代修改**：逐项修复并重新渲染，复查修改页与受影响页，最后全稿回归。交付文件必须就是最终通过检查的版本，验收后再改必须复检。

## 二、硬性设计与文案规则

| 项目 | 必须满足的规范 |
| --- | --- |
| 视觉基准 | 以用户提供的参考模板为基准，必须沿用其框图、文本框、配色和版式语言，禁止另起一套模板。具体执行[参考模板使用规范](references/template-guidelines.md)。 |
| 字体 | 未另行指定时全稿统一 Arial。检查 slide XML 全部 `a:latin`、`a:ea`、`a:cs`，包括 `lstStyle`、`endParaRPr` 和继承的有效字体，引用集合应为 `{'Arial'}`。禁止混入 Calibri、黑体或 `+mn` 等主题占位字体。缺字必须处理，不能默默换字体。 |
| 字号 | 默认所有可见文字至少 **18pt**，含图内文字的等效显示大小。含文本 run 的有效 `sz` 必须不小于 `2000`，表格、组合形状、页脚与继承字号不能漏查。禁止私自降到 16pt，例外必须有用户对当前任务的明确授权。 |
| 主视觉 | 每张正文页必须有支撑主题的图片或图表。自绘文字框加箭头只作侧栏、顶部条带等辅助，**禁止整页只有文字框流程图**，几枚装饰图标不能代替主视觉。 |
| 对齐与留白 | 整体内容围绕页面中轴平衡布置，左右留白对称，禁止整体偏向一侧而另一侧大片空白。图加侧栏的连续页面交替使用左右镜像布局。 |
| 封面与致谢 | 每段文字水平居中，文本框本身也居中，`left = (页面宽度 - 框宽) / 2`。不能只设段落居中。 |
| 文字容纳 | 文字必须完整位于容器内，无溢出、截断、异常断词或压线。放不下就加宽、精简、换行或拆页，禁止靠缩小字号过关。表格列宽按最长表头预留，换行列表使用悬挂缩进，结论条不得遮挡页码。 |
| 布局选择 | 三栏模板只用于真正的三栏结构，禁止把两栏或上下结构硬塞进三栏，也禁止多页机械套用同一版式。 |
| 文案与标点 | 自行撰写的中文页面文案和讲稿写成自然、完整的句子，标点只用逗号、句号、问号和冒号。**禁止关键词间圆点、破折号、英文 vs、斜杠分隔、箭头字符和用 × 表示数量**。停顿用逗号，对比与数量关系用完整句子表达。公式、网址和正式名称不作错误替换。 |
| 动画 | **不添加任何页面切换动画**，包括 morph 和淡入。只有用户明确要求时才启用。渐进展示用连续副本，必须覆盖全部中间状态，完整版放最后，删除节点时同时删除相关箭头。 |
| 内容与讲稿 | 数字、比值、时延、名称和分支逻辑逐条对照最终版原始资料的正文、公式、表格与图，计算须重新核算。遇到矛盾回溯证据并重新推导，有据修正并告知用户，无法确定时明确标记，禁止猜测。每页备注必须是可直接照读的第一人称口语稿，有具体内容和页间承接，修改内容同步改备注。 |

排字必须留约 **10%** 的余量。具体尺寸预算和中文渲染检查方法，见[排版与文件工艺](references/pptx-engineering.md)。坐标按当前页面尺寸和模板计算，不能套用其他稿件的固定位置。程序生成、换图、裁图、复制合并或底层 XML 修改前，必须读取该附录对应部分。

## 三、素材、图片与图标

- **主动多搜集**：优先用户原始资料与官方来源，再补充网络素材。正文页的关键对象和内容块应配相关图片或图标，逐页检查遗漏，不能用纯文字卡片替代素材搜集。没有总览图时，可组合各步骤的真实图片或论文面板，不虚构来源。
- **图片可以缩小作 icon**：实物图、产品图或素材图可裁切、去背景并缩小作为图标，不能只依赖现成图标库。缩小后主体必须可辨认，同组视觉尺寸和风格统一。
- **必须实际嵌入**：检查原图内容、清晰度和版本，记录出处，嵌入最终文件。禁止保留链接占位、空框或“此处放图”。生成图只作示意，不冒充真实产品、实验结果或数据证据。
- **比例与裁切必须正确**：保持纵横比，换图同步检查图框和旧 `srcRect` 裁切，不能拉伸图片或裁掉图例、标签与面板。只处理目标图片，禁止批量清除其他页面的有意裁切。
- **图内信息必须可读**：按最终显示尺寸检查文字与细节，达不到字号要求就放大局部或拆页。图上高亮不得压字压线，密集图优先用无描边半透明色块。与当前原始资料逐图比对，防止标题和结论已更新，配图仍是旧版本。

## 四、验收门槛

**以下项目全部通过，才能称为完成。没有工具、时间不足或脚本成功都不是豁免理由。** 无法执行的检查必须标明未通过验收，不得用另一种检查冒充。

1. **程序检查**：检查字体集合、有效字号、禁用标点、页序、备注及图片关系。PPTX 必须通过 ZIP 完整性检查、重载检查，无重复 ZIP 成员、重复页内形状 ID、悬空关系或重复 `avLst/gd` 参数名。详见工艺附录。
2. **全页渲染检查**：渲染最终 PPTX，逐页打开查看，局部放大核对。必须看见实际中文字形，不能拿豆腐块或缺字图验收。检查溢出、断词、重叠、对称、孤箭头、图片失真、错误裁切、空带、页脚和模板残留元素。图片内文字也要看，不能只抽取可编辑文本。
3. **至少三轮子 agent 交叉验收**，每轮发现问题后先修复再进入下一轮。
   - 第一轮，视觉验收 agent 与事实核对 agent 并行，事实检查包含算术自洽、分支逻辑和图文版本一致。
   - 第二轮，交叉审查 agent 逐项验证修复并检查回归，另一个独立视觉 agent 从新视角逐页查漏。
   - 第三轮，最终联合验收，全页扫描并复核修改页事实。仍有问题就继续修复复检，不能把三轮当作停止条件。
4. **真实 PowerPoint 开箱**：最终 PPTX 必须在真实 PowerPoint 中用副本打开，无修复弹窗、空白页或内容丢失，并核对页数。LibreOffice 渲染、python-pptx 重载和 XML 校验均不能替代。检测器先用已知良好文件验证，不能把应用恢复状态或脚本报错直接判为文件损坏。

每条问题记录 **页码、具体位置、放大截图或数值证据、修复结果、复检结果**。字体字号、标点、缺图、不可读、事实错误、文件异常或误改任一项不合格，均不得交付为已完成。完整验收后保持最终文件不再变化。

## 五、修订、交付与经验维护

- 接手先查 `mtime`，以用户最新版为基准。同目录创建带编号的 `*_backup<N>.pptx`，只改指定页，保留用户手改的文字、图片、几何与格式。写回前再次确认源文件未被用户更新，禁止重跑旧脚本覆盖手改。
- 全部修改完成后先保存到临时文件，检查通过再替换目标文件。保存出错时废弃损坏产物，若原件已受损立即从备份恢复，不在坏文件上继续修改。
- 备注按讲述时长编排，英文可按约 130 词每分钟预算，中文按实际试读计时。渐进页注明阶段和一句讲解，完整页保留整段讲稿，重排后逐页核对备注对应关系。
- 交付最终文件、备份位置和简短验收记录，注明实际使用的软件、三轮检查结果、PowerPoint 开箱结果及用户明确接受的例外。
- 新发现的失败模式、实测数据或更优做法，必须在当次会话更新本 skill 或对应附录。合并重复规则，保留适用条件，禁止以精简为由删除已有硬规范。
